# 天空里的云：形体与上色

> WO-20（上色）+ WO-30（形体），2026-10-12 → 2026-10-14。
> 代码：`src/config/skyClouds.js`（摆位/层片）· `src/shaders/skyClouds.js`（形体/上色）·
> `src/components/canvas/entrance/SkyClouds.jsx`（每帧喂 uniform）·
> `src/utils/cloudArt.js`（素描底，未改）。
> 判据：`.workbuddy-ai/harness/probe-sky-clouds.mjs`（P1~P7 纯数据 + S1~S6 浏览器）。

用户原话（第三轮）：「云朵搞逼真一点（是否上 glsl）」→ 拍板 **(A) billboard + GLSL 片元**。

---

## 0. 为什么不是真 raymarch

参考实现的云是 `MarchingCubes` 雕的 metaball，一次烘焙 ≈ 340 万次距离计算 × 4 变体，
它有一次性的 loading 屏，本项目没有。而且全屏每像素积分与本项目的**三级降级**
（HIGH/MEDIUM/LOW）正面冲突 —— 那套降级是"低端机上少算"，不是"少画几个像素"。

所以定成：**保留 billboard，把"形体"交给片元**。代价 **0 新增 mesh / 0 新增 draw /
0 新增贴图**（实测见 §7）。

## 1. 剪影：从"画好的死边"到"被噪声侵蚀"

现状的边是 canvas 画好的**一条曲线一笔到底**，这是最大的"假"源。

🔴 **非显然的一步**：素描的 `alpha` 是 **1 像素的硬跳变**。直接把 fbm 噪声减到阈值上，
阈值挪 0.22 在空间上**只挪 0.22 像素** —— 数学上成立，**像素上为零**。
所以必须先模糊出一张**软高度场**（≈"离边缘多远"），阈值挪 Δ 才等于把边挪
`Δ × 模糊宽度`。

```glsl
float soft = cover(vUv, uSoftR);              // 3×3 二项核，半径 uSoftR
float cut  = 0.5 + (n - 0.5) * uErode;        // n = fbm(vUv * uNoiseScale + seed)
float a    = smoothstep(cut - uEdge, cut + uEdge, soft) * uOpacity;
```

- 核用**整块 3×3 二项核**，不是十字核：十字核的坡度分段常数、拐点有折角，
  拿它当高度场会出现可见色带。
- 种子从**世界位置**派生（`vW`）⇒ 一朵云的三个层片花样不同，同一朵云每帧相同
  ⇒ 确定性、可复现，且**不需要新增 instance 属性**。

`ERODE = 0.22`：换算 `rms ≈ 0.15 × ERODE/2 × 2 × SOFT_R`。不能再大 —— 实测最大摆幅
13.42 px 已经≈墨线环的屏上厚度，再大**描边就断了**。

## 2. 明暗：解析半球（以及一条走过的弯路）

原来只有 `uv.y` 的竖向渐变。WO-30 要"按太阳方向"。

### ❌ 走过的弯路：把贴图 alpha 模糊成高度场、梯度当法线

听上去很顺：面片没有几何法线，但"离边缘多远"那张场的梯度就是一朵云的**朝外方向**。
**实测不行。** 贴图 alpha 里有**内部结构**（墨线弧、瓣轮廓），模糊之后那些弧主导了梯度
⇒ 法线**沿着墨线乱翻**，"有方向"退化成"有噪声"：

| 量具 | 数值 |
| --- | --- |
| 朝阳半 − 背光半 | **2.5 / 255** |
| 单像素最大 \|ΔL\| | 37 / 255 |

而且把 `SHADE_R` 从 0.10 调到 0.24、`BUMP` 从 0.4 调到 1.4，那个"2.5"几乎不动 ——
一个**不随调制强度变化**的方向量，本身就是"这不是方向"的证据。
证据图 `.workbuddy-ai/.tmp/wo30-sunmap/sun-dL.png`（改之前：暗/亮曲线完全**沿墨线**）。

### ✅ 现在：一颗解析半球

```glsl
vec2 p   = (vUv - 0.5) * 2.0 * uDomeSpread;
vec3 nrm = normalize(vec3(p, sqrt(max(0.0, 1.0 - min(dot(p, p), 1.0)))));
float ndl = dot(nrm, normalize(uSunCam));
```

- 与墨线**无关**，`|p|` 到 1 就是半球边缘；`DOME_SPREAD = 2.0` 让**云的轮廓**正好落在
  边缘上（素描里那朵云半宽 ≈ 0.25 UV ⇒ `0.25 × 2 × 2.0 = 1.0`）。
- **0 次贴图采样**（比弯路那版少 9 次），也不需要 `dFdx/dFdy`
  ⇒ 顺带消掉"导数必须在 discard 之前"那条约束。
- 面片局部基 = **相机基**（billboard 每帧抄的就是相机四元数），所以 `nrm` 与
  `uSunCam`（CPU 侧用**同一个** `camera.quaternion` 换算）同基。
  ⚠️ 用 `camera.matrixWorld` 会差一帧，明暗就和朝向对不上。

### 🔴 抬/压必须是**乘性**，不能写 `mix(c, uTop, …)`

因为 `c` 自己就是 `mix(uBottom, uTop, vUv.y)` —— 在云顶那一片 `c ≈ uTop`，
于是 `mix(c, uTop, sunAmt)` 在那儿**几乎无效**，而"朝阳的那一侧"恰恰经常落在云顶。

```glsl
float lit  = max(ndl, 0.0) * uSunAmt;
float dark = max(-ndl, 0.0) * uShadeAmt;
c *= 1.0 + lit - dark;
```

乘性调制对 `c` 的任何取值都有效，而且**不引入第二个色源** —— 调的就是已经派生的 `c`
本身（契约见 §5）。

## 3. 一朵云叠 3 层薄片（视差）

`config/skyClouds.js` 的 `expandLayers()`：14 条**逻辑摆位** `SKY_CLOUD_PLACEMENTS`
（冻结、逐位锚点 `947.959130`）向外径向展开成 **42 条实例**（每槽位 `[15, 15, 12]`）。

- 沿**岛心 → 云**的径向**外推**（0 / +3.2 / +6.8）并且**放大**（×1.00 / 1.07 / 1.14）
  ⇒ 远的层从近的层后面露出来，否则内层把外层整条挡住 = 白画。
- 再加一点**切向**偏移（±0.8 / ∓1.05）⇒ 三条剪影不重合。
- 第 0 层与逻辑摆位**逐位相同** ⇒ P1 的锚点不变。
- **仍然只有 3 次 draw**（还是一个槽位一个 `InstancedMesh`，只是 `count` 从 14 变 42）。

## 4. 为什么"看起来斜"不是 bug

`ORBIT_MIN_ELEV = 0.017` 那种贴地机位下，地面平面在屏幕上看起来是斜的 ——
那是**透视的固有结果**，不是几何错了。判据要看**轮廓主轴角**，不是"像不像水平线"。

---

## 5. 🔴 颜色只有一个真源

云顶/云底/朝阳色**不在云里另立色板**，每帧从天空穹顶（`SceneLighting.jsx` 的
`name="sky-dome"`）的 `uZenith / uHorizon / uCloud / uGlow / uSunDir` 派生。

理由（本项目栽过一次）：同一个事实存两份，迟早不同步。
若云自己算一遍季节色 ⇒ ① 换季时天变了云没变；② 昼夜过渡（0.9 s）时天空在插值、
云**不插** ⇒ 天黑了云还亮着。从穹顶读就**不可能**不同步。

🔴 查法是**按 `name` 查**，不是按"有没有某个 uniform"猜。以前写的是
`o.material?.uniforms?.uStrata` —— 于是"这是显式接口"在代码里并不成立：
改名不报警，删掉 `uStrata` 反而**静默失联**。WO-30 改成按名字查 + 找不到只警告一次。

## 6. 判据与实测（2026-10-14）

### 纯数据段 P1~P7（不需要浏览器，打不进假绿）

| | 判据 | 实测 |
| --- | --- | --- |
| P1 | 确定性 + 冻结 + 逐位锚点 | 坐标和 `947.959130`，分区 `14/14` |
| P2 | 不切航线 | 最小间隙 `6.04`（需要 ≥ 4.00） |
| P3 | 在穹顶里 | 最外缘 `115.33 < 138.00` |
| P4 | 在地面之上 | 云底 `12.17 > 0` |
| P5 | 抬头看得见 | 高度角 `15.8°~25.4°`（需要 10°~29.9°） |
| P6 | draw 数 = 槽位数 | **3**；实例 `42 = 14 × 3`（每槽位 `[15, 15, 12]`） |
| P7 | 层片几何 | 每朵 3 层；第 0 层逐位等于逻辑摆位；最近两层间距 `3.31 > 1`；越外越远、越外越大（最小比 `1.065`） |

🔴 **P2~P5 跑的是「层展开后的真实实例表」**，不是那 14 条逻辑摆位 ——
层片是真的几何，只验逻辑摆位等于给一个假绿。

### 浏览器段 S1~S6（真渲染的像素）

| | 判据 | 实测 |
| --- | --- | --- |
| S1 | 量具噪声底（同参数两跑逐位相同） | `rough 3.865193` vs `3.865193`；`r(θ)` 360 点逐位相同 |
| S2 | **剪影不再是死边** | 边缘摆幅（`Δr` 去均值）rms **2.124 px**、最大 **13.42 px**（需要 ≥1.2 / ≥2.0，上界 14.4 px） |
| S3 | 形体没被改坏 | 平均半径 `288.35 → 288.93`（**0.20%**，需要 ≤6%） |
| S4 | 太阳方向真的有方向 | 朝阳半 `+11.53` vs 背光半 `−9.75`（差 **21.28**，需要 >2.0）；`maxAbs 28.64`（需要 >8） |
| S5 | 低档真的少算 | `deviceMemory=2 ⇒ uDetail = [1,1,1]` |
| S6 | 页面错误 | 0 |

S4 的旁证（不作断言）：沿太阳方向 ±0.35 两条窄带 日侧 `+12.69` / 影侧 `−15.96`（差 28.65）；
`ΔL` 与"对齐度"的相关系数 **corr = 0.753**（+1 = 完全按太阳方向）。

### 🔴 S2 量的是 `Δr(θ) = r_开(θ) − r_关(θ)`，不是直接量 `r(θ)` 的高频

`r(θ)` 里**本来就有**一大堆高频 —— 云是有瓣的，从质心出发的射线会在瓣与瓣之间**跳变**
（实测：侵蚀关掉时 `rough` 就已经 4.14 px）。那是**云的形状**，不是"边毛了"。
两次渲染里云的瓣一模一样 ⇒ 相减即抵消，剩下的**只有侵蚀把边推开的量**。

## 8. 三档定妆照

`.workbuddy-ai/.tmp/wo30-tiers/{HIGH,MEDIUM,LOW}.png`
（机位 `?flight&t=13.2`，见下；冻结飞行时间 ⇒ 机位逐位确定）

| 档 | 档位（直读 `window.__tier`） | `uDetail` | 画面指纹 |
| --- | --- | --- | --- |
| HIGH | HIGH | `[3,3,3]` | `d0e4696a` |
| MEDIUM | MEDIUM | `[3,3,3]` | `d0e4696a` |
| LOW | LOW | `[1,1,1]` | `576d4ef4` |

⚠️ HIGH 与 MEDIUM 指纹相同 —— 两者的差别是 `dpr`（这台机器三档都解析成 1）、
`antialias`（都开）和 `particleCount`（1.0 / 0.6），在**这个机位**上不一致的东西
刚好都不在画面里。三张仍然各自拍对了档位（`window.__tier` 是**直读**的，不是反推）。

两个坑（都写进 `shot-cloud-tiers.mjs` 的文件头了）：

1. **光伪造硬件信号不够**。`PerformanceMonitor` 按**真实 fps** 降档，而本环境
   （swiftshader + dev）只有 ~1 fps ⇒ 三页**全被降成 LOW**，连 `cores=真值`
   的 HIGH 那页也是。修法是应用侧留一个 dev 闸 `window.__tierLock`
   （**只锁降档，不碰 `detectTier()`**，所以档位仍由伪造信号真判出来）。
   ⚠️ 别去掰 `Clock.getDelta` —— 那个监视器数的是真实帧、读的是
   `performance.now()`，掰时钟完全无效（白跑两轮）。
2. **`?orbit` 框不住云**。相机被钉在 `r ≤ ORBIT_MAX_R = 38` 上且**永远瞄准岛心**，
   而云在半径 ~51、高度 12~25 ⇒ 最近的几朵全在竖向 fov（半 fov 30°）之外，
   整张照片里云只是屋顶上方几个小白点。改用 `?flight&t=13.2`：
   `flightCameraAt(13.2)`（`FLIGHT_DURATION = 44`）把相机放在 **y = 22.1**，
   正是云层高度、朝外看。

## 9. 一句话总结

云是**一张画**（素描底 + 墨线），不是几何。WO-30 动的是**它的轮廓怎么被噪声侵蚀**、
**它的身子怎么被太阳照亮**、**三片薄片怎么错开** ——
三件都在片元里，所以画质上去了，**代价是 0**（§7）。
