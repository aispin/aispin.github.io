# 实验环 · RING GALLERY

一圈悬浮的玻璃展板，滚动 / 拖动转动，正前方那块被"抽"出来；点开在 **iframe
浮层**里直接体验，不跳走。

一个**可复用的落地页模式**，不是某个房间的专用页面。它解决的是这一类需求：

> 有 N 个互不相干的东西要展示，每个都值得点进去玩一下。

站内「创意实验」房间目前就是用它当静态原型 —— 但页面本身不认这个房间：
换掉 `GROUPS` 和 `fetch` 的地址，就是另一个画廊。

---

## 三层，任何一层都能单独换掉

| 层 | 做什么 | 换它要改哪里 |
| --- | --- | --- |
| 环境层 | 全屏 GLSL：五倍频 fbm 星云 + 星点 + 环心冷光 + 暗角，鼠标轻微视差 | `FRAG` 里三个 `vec3`（底色 / 靛蓝 / 紫） |
| 展板层 | N 块展板绕成一圈，转到位的那块放大、抬起、加扫光 | `buildLab()` 的输入、`GROUPS` 的类别表 |
| 体验层 | 点焦点板 → iframe 浮层 | `openViewer()` 里 `viewerFrame.src` 换成别的（视频、代码、文档） |

## 为什么不用 CSS 3D

`perspective` + `rotateY` + `translateZ` 看起来是最省事的路，但**几何上做不到**：

- 要让正前方的展板保持 ~250px 的可读尺寸，透视距离 `P` 必须远大于环半径 `R`；
- 而水平视角 = `2·atan(W / 2P)`，`P` 一大视角就只剩 20° 上下，一屏两块板，
  环不成其为环；
- `P` 一旦接近 `R`，靠相机的那些板又会被透视放大到糊满屏幕。

所以这里**自己算圆柱投影**：

```
θ  = (i − cur) · 2π/N          这块板离正前方多少弧度
x  = f · tanθ                  等角映射，越靠边越稀
s  = 1 − 0.18·(|θ|/MAX)²       两端收一点，假装有纵深
a  = 1 − (|θ|/MAX)²            同上，用透明度做空气透视
```

相机就在圆心 ⇒ 每块板到相机的距离恒为 `f` ⇒ 视觉宽度恒等于板宽，只在两端衰减。
这正是 3D 房间里一台 `PerspectiveCamera` 看到的东西，数字可以直接搬。

## 焦距不能写死

```
spacing = pw × 1.16
f       = spacing / tan(2π/N)
MAX     = atan(半屏宽 × 0.92 / f)
```

先定板宽和缝、再反算 `f`，于是"一屏看见几块"是**自然结果**：桌面 4 块、手机 1 块。
写死视角会在 390px 上崩 —— `f = 195/tan31° = 324`，相邻展位只隔 83px，
而板宽最小 150 ⇒ 五块板叠成一团，还把左栏压没。

## 数据

默认读 `../../demos.json`（构建脚本扫 `public/demos/` 生成的索引）：

```js
{ "demos": [ { "id": "web3d/career", "title": "…", "url": "/demos/web3d/career/", … } ] }
```

类别取 `id` 的第一段路径（`web3d/career` → `web3d`），认不出的落进 `misc`。
**往 `public/demos/` 丢一个新目录，环上就自动多一块板。**

环上会排除这一页自己 —— 靠 `SELF_ID`（从 `location.pathname` 推），
所以换个目录名、或者把整页复制成第二个画廊，自我排除仍然成立。

## 交互

| 操作 | 结果 |
| --- | --- |
| 滚轮 / 触控板 | 转一格（攒够 42 的 deltaY 才动，避免一次长划连跳几块） |
| 拖动 | 跟手转，松手吸附到最近一格 |
| ← → ↑ ↓ | 转一格 |
| Enter | 打开当前这块 |
| 点焦点板 | 打开浮层 |
| 点别的板 | 先把它转到前面（不直接开，避免手滑弹出浮层） |
| Esc / 点遮罩 | 关浮层 |

## 已知的坑

- **不要用 `setPointerCapture`**：捕获后浏览器把 `click` 派发到捕获元素上，
  展板的点击就永远收不到，表现为"板子点不动"。改成 `pointerdown` 记起点、
  `pointermove` / `pointerup` 挂 `window`，再用位移阈值抑制"拖完补的那次 click"。
- **浮层里要注掉 demo 自己的返回胶囊**：`_lab.css` 的 `.lab-back` 会把 iframe
  导去索引页，用户困在浮层里。同源可以往 `contentDocument.head` 塞一条样式；
  跨源会抛，`catch` 掉即可。
- 环上最边上那块板会压在左侧类别栏后面 —— 靠加深 `stage` 的 mask 会把它整个
  抹掉（那是内容），所以改成给左栏垫一层 `backdrop-filter: blur()` 的局部暗角。

## 尺寸 / 性能

- 环境层 DPR 上限 **1.5**：纯背景，2x 屏多出来的像素只是多烧 4 倍填充率。
- 展板是 DOM，不是贴图 —— 文字天然清晰，也不需要为每块板生成 canvas 纹理。
- `prefers-reduced-motion` 下：星云停止漂移、扫光动画关闭、视差归零，
  但**转动仍然跟手**（那是用户自己发起的运动，停掉反而让界面失灵）。
