# 黑胶 · VINYL — ZEO 的音乐唱片机

一首歌怎么被**看见**？不是再摆一堵卡片墙 —— 音乐房间的空间轴是**时间**，所以这里只有
**一件实物**：一台真的会转、真的会响的唱盘。封套是作品，唱片是声音，唱臂是时间，
唱片边缘那圈短针是"正在发生的事"。

- 入口：`index.html`
- 在线预览：`/demos/web3d/vinyl-player/`
- 调试参数：`?theme=light|dark`、`?lang=zh|en`（不给就**随系统**）
- 数据：`public/data/netease-music-zeo.json`（构建产物，见「数据从哪来」）
- 探针：`node .workbuddy-ai/harness/probe-vinyl.mjs`（40 条断言，见文末）

## 歌单条：三张歌单卡 + 一排专辑卡

唱盘只有一个，但唱片可以换。右栏顶上是一块**歌单条**，都接到同一台机器上：

| 卡 | 来源 | 说明 |
| --- | --- | --- |
| **精选** | `src/data/music.json` | 手挑的几首，永远是首屏；不依赖网络 |
| **最新** | 构建产物 `latestSongs` | 按专辑发行时间倒序，同专辑按曲序 |
| **最热** | 构建产物 `hotSongs` | 官方「歌手热门 50」的顺序 |
| **专辑**（一排） | 构建产物 `latestAlbums` | 点一张 = 整张专辑上盘 |

两层，**同一块**：上层三张等宽矮卡（名字 + 大数字 = 这张列表多少首），
下层是 76×94 的专辑卡（主色条 + 右上角「专辑」角标 + 名 + `EP · 年份`）。
两类卡靠**内容**区分而不是靠颜色 —— 这一栏已经很密，再上色块就吵了。

> 为什么不是**一排**混着放：7 张 76px 的卡塞不进 330px 的一行，硬塞的结果是
> 专辑全被推到横向滚动后面（等于没有入口）。所以同一块里分两层，各有各的宽度逻辑。

**品牌位不写曲目数**（`ZEO · 精选集`）。作品会一直加，把「06 首」焊在标题上是
最容易被时间打脸的一行字；曲目数只在列表表头里按**当前这张列表**实时算。

## 为什么是唱盘（而不是"音乐版卡片墙"）

房间之间不能撞车，这是这个站的一条硬规矩：

| 房间 | 空间语言 | 表达什么 |
| --- | --- | --- |
| career | 纵向隧道 | **序列**（一段一段往前走） |
| craft | 环形展板 | **并列**（同时都在） |
| posts | 一条经折长卷 | **长度**（篇数涨了只是带子更长） |
| ai | 弧形卡片墙 | **收藏**（一堆同质的东西） |
| **music** | **一件实物** | **时间**（针从外圈走到片芯 = 一首歌的长度） |

所以音乐房间不摆墙，摆**一台机器**。曲目列表退到右侧当"唱片内页"，主角是那件实物。

## 交互

| 操作 | 结果 |
| --- | --- |
| 点播放键 / `空格` | 放 / 停（`<audio>` 的 `play`/`pause` 事件是唯一真源） |
| 点曲目行 / `↑` `↓` / 滚轮 | 换曲并**直接开播**（换曲 = 换唱片，不放没意义） |
| 点 **精选 / 最新 / 最热** 歌单卡 | 换一张列表；正在放的那首不会被切掉，表头跟着变 |
| 点**专辑卡** | 整张专辑上盘：列表换成它的曲目，从第 1 首开播（卡片亮起） |
| 在歌单条 / 曲目列表上滚轮 | 滚的是**内容**（专辑条横滚、列表竖滚），不换曲 |
| 拖**唱臂** | 跳转 —— 抓的是臂，改的是角度，针跟着沟走（拖的时候自动暂停，松手接着放） |
| 拖进度条 / `←` `→` | 跳转（同一个"进度"的两个把手） |
| `Enter`（焦点在曲目行上） | 换曲 |
| 一首放完 | 自动下一首（`ended`） |

## 数据从哪来

页面**不碰**网易云接口 —— 构建时抓一次，存成同源静态 JSON：

```
packages/netease-artist  ──npm run data:music──▶  public/data/netease-music-zeo.json
        ↑ 给音乐人 id，产出 基本信息 / 最新 N 首 / 最热 N 首 / 最新 N 张专辑
```

```bash
npm run data:music     # 重新抓 ZEO 的（id 49232788 写在 package.json 里）
```

`packages/netease-artist` 是个**独立包**（零依赖，别的项目也能用），
细节见它自己的 README。拉不到 JSON 时页面只显示精选集 —— 离线不该白屏，
但也不会假装有数据（「最新 / 最热」两个 tab 直接置灰）。

## 三个设计决定，都是"3D 必须有用"

**1. 唱臂角度 = 播放进度，而且可以直接拖。**
真实唱机上针从外圈走到片芯就是一首歌；这里把它做成可交互的进度条 —— **时间有了实体**。
角度不是线性插值：给定"针到圆心的半径" r，用余弦定理反算臂角
`r² = P² + L² − 2PL·cos θ`，所以针真的贴着沟走（线性转臂会让针中途跑到盘外）。

**2. 频谱从唱片边缘长出来，画在唱片所在的平面里。**
它和唱片共享同一次 `rotateX(52°)`，所以是"盘在震动"，不是"UI 在跳"。

**3. 唱片永远是黑的、封套永远是纸的，只有页面（墙）跟随深浅色。**
这两个是"桌上的实物"，换主题不该把它们也漂白 —— 浅色主题下一张黑唱片压在暖纸上，
正好是整页的视觉锚点。**浅色不是把深色反相。**

## 🔴 网易云外链：能放，但没有 CORS（所以频谱是程序化的）

```
302 music.163.com/song/media/outer/url?id=…  →  http://m701.music.126.net/…
```

- **302 那一跳不带 `Access-Control-Allow-Origin`**（末端 CDN 带，没用）。
  ⇒ 一旦 `<audio crossOrigin="anonymous">`，直接 `ERR_FAILED`：**一挂 CORS 连播放都没了**。
  ⇒ 也拿不到真 FFT：`createMediaElementSource()` 对非 CORS 音源按规范输出**静音**，
  那才是"为了频谱把歌弄哑"。
- 302 指向 `http://`，但实测在 https 页面上 Chrome 会自动升级成 https，**线上播放没问题**；
  有问题的只有 CORS。
- 所以那圈短针是**程序化**的：以曲目 id 为种子、以 `audio.currentTime` 为时间轴，
  叠三个不可通约的正弦 + 一个"拍"。它反映的是"针正在沟里走"，不是"我在分析音频"。
  暂停 = 停针 = 环定住，这恰好是对的。
  以后要是把 6 首换成**站内文件**（同源），把 AnalyserNode 那段接回来即可。

## 屏幕 ↔ 平面：透视不是仿射

`.deck__plane` 上只有一次变换 `rotateX(52deg) rotateZ(-7deg)`，外面再乘一个
`scale(s)`。一开始把反解写成"乘一个 2×2 逆矩阵"（等于当正交投影），
结果**盘边误差 ~30%**：900 见方的平面在 `perspective:1600px` 下，近端 `s≈1.33`、
远端 `s≈0.84` —— 拖唱臂时指针和手指会分家。现在的 `screenToPlane` 是闭式解：

```
A = x·cosZ − y·sinZ          B = x·sinZ + y·cosZ
Y2 = B·cosX ,  Z2 = B·sinX    s = k / (k − Z2)      k = 1600
```

`perspective-origin` 是 `50% 42%`（**不是中心**），差的那 72px 也算进去了。
`planeToScreen` 与真实 DOM 变换在中心与盘边三点上的误差都是 **0.00px**（探针断言）。

## 踩过的坑

- 🔴 **放歌的时候抓不住唱臂**（这条查了三轮才找对根因）。
  第一版以为是"`#discArt` 一转起来自成合成层、抢了命中测试"，给 `.arm` 加
  `z-index:3` —— **完全没用**。真因是两条叠在一起：
  1. `.deck__plane` 是 `preserve-3d`，**那里 `z-index` 不参与排序**（按 3D 深度排），
     所以盘面那两块 canvas 永远盖在唱臂上面接走 `pointerdown`；
  2. 更要命的是 **`elementFromPoint` 和真实 pointer 命中在这个子树里是两条不同的
     路径**：它报 `.arm__rod`，真按下去事件却落到 `.deck__plane` 上（只有臂两端
     那两个自带合成层的小块能命中）。所以"按元素位置算命中"这条路根本不成立。
  现在**命中判定自己算**：`.arm`、`.disc`、`.sleeve` 全部 `pointer-events:none`，
  监听挂在 `.deckwrap`（普通 2D 元素，命中可靠）上，把指针换算成平面坐标，量它到
  "支点 → 针尖"这条线段的距离（±26px 容错，支点后面的配重也能抓）。
  ⇒ 判据只能是"真按下去、真拖、看 `currentTime`"；`elementFromPoint` 不能当证据。
- 🔴 **拖针时先暂停**：不停的话播放头还在往前走，每挪一像素又 seek 一次，两边互相
  拽 —— 手感就是"拖着拖着被弹回去"。松手再 `play()`，和真实唱机按住唱片挪针一样。
- 🔴 **透视投影下四边形的 bbox 中心 ≠ 它的中心点**（近边放大得多，bbox 整体往近边偏
  ~70px）。验投影必须插一个 0×0 探针元素读 `getBoundingClientRect()`，不能拿
  `#disc` 的 rect 中心当标准答案 —— 第一版就是这么"验失败"的。
- 🔴 **拖唱臂不能拿"指针到支点的距离"当"针到圆心的半径"**：针离支点 216、离圆心 285，
  抓针尖会一下跳到 40%。要按**角度**算。
- 🔴 **探针别拿"当前进度对应的角度"当"臂现在在哪"**：暂停时臂停在 `t=0`，
  按 `t=0.5` 算出来的采样点全在空地上 —— 会得出"命中框根本不存在"的错误结论。
  要先读 `state.armNow`。
- `.track__title` / `.track__sub` 必须 `display:block`，否则两个 span 挤成一行
  （`Bb - Rooftop's rainPhrygian · 2021`）。
- **列表装不下时最后一行是被裁的**（最新/最热有 12 首）。溢出的才加
  `.tracks.is-scroll`，给末行一道 `mask-image` 渐隐；列表短时不加，末行边框保持完整。
  ⚠️ 渐隐只能 **10px**：`.track` 的 padding 是 17px，行被裁时标题正好落在
  10~30px 那一段，26 / 16 都会把整行标题糊成"幽灵"（看着像渲染坏了）。
- 🔴 **在曲目列表上滚轮会跳歌**（用户报的 bug）。`window` 上那个"滚轮 = 下一首"
  是无条件的；现在先问一句"指针这一路有没有还能滚的容器"（`wheelScroller()`），
  有就把滚轮让给它。
  ⚠️ 让给它之后还有第二个坑：**Chrome 不会把竖滚轮转成横滚**（专辑条是
  `overflow-x:auto`），所以鼠标用户在那一排上滚 = 什么都没发生。得自己
  `scrollLeft += deltaY`，监听因此从 `passive:true` 改成 `passive:false`。
- 🔴 **触摸屏上滑动还是会跳歌**（同一条 bug 的第二轮）。原因是 Chrome 在部分平台
  （Windows 触屏、部分 WebView）**把手指的滑动也派成 `wheel`**，而且手指划在
  唱盘那块（不可滚）上时，"有没有能滚的容器"根本挡不住它。两道闸：
  1. `e.sourceCapabilities.firesTouchEvents === true` ⇒ 这是手指，不是滚轮；
  2. 兜底：`touchstart` / `touchmove` 记时间戳，800ms 内的 `wheel` 一律不换曲
     （老引擎没有 `sourceCapabilities`）。
  ⚠️ 顺带一条同源的：**滑完列表手指抬起会被派成 `click`**（惯性滚动时更明显），
  落在某一行上就等于"选了那一首"。所以行点击里加了一句"刚滚过 350ms 内不算点"，
  只在最近 900ms 有过触摸时生效 —— 鼠标点击完全不受影响。
- 🔴 **专辑卡 hover 时顶边框被裁**（用户报的 bug）：`.shelf__row` 是
  `overflow-x:auto`，另一个轴会算成 `auto` ⇒ 卡片 `translateY(-2px)` 抬出去的那
  2px 被裁掉。给滚动容器加 `padding-top:4px`（内容区往上让出抬起的余量），
  判据是 hover 后 `card.top − row.top ≥ 0`。
- 封套的字位放在**顶部**：唱片压在上面，只让出顶部一条横带和左边一条竖带。
  字放下面会被唱片盖掉。
- canvas 上的字体是异步的，`document.fonts.ready` 之后要重画一次，否则字宽不对、排版错位。
- 浅色主题下频谱环要用**深**主色（纸上的浅蓝几乎看不见），而且更短更淡，否则像一圈尖刺。

## 主题与语言

和 `ai-atlas` / `posts-fold` 一样：**没有**切换图标，深/浅色与中/英都由 3D 房子统一控制
（`SitePreferences` 写 `html[data-theme]` / `data-lang`）。`../../_env.js` 只让独立页面
能模拟这套环境，解析优先级 `?theme=` > 宿主预写 `data-*` > 系统，
结果通过 `stageEnv.onChange` 通知本页（文案、封面、片芯、主色、WebGL 底全部跟着重画）。

## 探针（`probe-vinyl.mjs`）

截图看不出来的**空间**断言，一共 54 条：投影正/反解与真实 DOM 一致（±1.5px）、
往返误差 < 0.5px、t=0/1 时针落在 0.95R / 0.38R、真的在放（`currentTime` 前进）、
唱片在转、**播放中用真鼠标**抓臂（抓住即暂停）→ 拖到 92% → 松手接着放、
点盘面不会误抓、6 行曲目 / 只有 1 行高亮 / 点第 3 行换曲换主色换音源、
**构建产物真的被用上了**（最新 12 首 / 最热第一首 = 官方热门第一 / 点专辑整张上盘）、
品牌位不写死曲目数、空格暂停、中英文案切得动、
**歌单卡上写着曲目数 / 专辑卡有「专辑」角标 / 两类卡在同一块里**、
**专辑卡 hover 顶边不被裁**（量 rect）、
**滚轮在列表上滚列表不换歌、在专辑条上横滚不换歌、在唱盘上仍然换歌**、
**手指刚动过滚轮不换歌 / 静置后照旧换歌 / 刚滚过列表点行不算点**、无运行时错误。

```bash
node .workbuddy-ai/harness/probe-vinyl.mjs            # 默认打 5199 的 dev
node .workbuddy-ai/harness/probe-vinyl.mjs <url>      # 也可以打 dist
```
