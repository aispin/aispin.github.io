# 黑胶 · VINYL — 六首原创音乐唱片机

一首歌怎么被**看见**？不是再摆一堵卡片墙 —— 音乐房间的空间轴是**时间**，所以这里只有
**一件实物**：一台真的会转、真的会响的唱盘。封套是作品，唱片是声音，唱臂是时间，
唱片边缘那圈短针是"正在发生的事"。

- 入口：`index.html`
- 在线预览：`/demos/web3d/vinyl-player/`
- 调试参数：`?theme=light|dark`、`?lang=zh|en`（不给就**随系统**）
- 探针：`node .workbuddy-ai/harness/probe-vinyl.mjs`（25 条断言，见文末）

## 为什么是唱盘（而不是"音乐版卡片墙"）

房间之间不能撞车，这是这个站的一条硬规矩：

| 房间 | 空间语言 | 表达什么 |
| --- | --- | --- |
| career | 纵向隧道 | **序列**（一段一段往前走） |
| craft | 环形展板 | **并列**（同时都在） |
| posts | 一条经折长卷 | **长度**（篇数涨了只是带子更长） |
| ai | 弧形卡片墙 | **收藏**（一堆同质的东西） |
| **music** | **一件实物** | **时间**（针从外圈走到片芯 = 一首歌的长度） |

所以音乐房间不摆墙，摆**一台机器**。曲目列表退到右侧当"唱片内页"，主角是那件实物。

## 交互

| 操作 | 结果 |
| --- | --- |
| 点播放键 / `空格` | 放 / 停（`<audio>` 的 `play`/`pause` 事件是唯一真源） |
| 点曲目行 / `↑` `↓` / 滚轮 | 换曲并**直接开播**（换曲 = 换唱片，不放没意义） |
| 拖**唱臂** | 跳转 —— 抓的是臂，改的是角度，针跟着沟走 |
| 拖进度条 / `←` `→` | 跳转（同一个"进度"的两个把手） |
| `Enter`（焦点在曲目行上） | 换曲 |
| 一首放完 | 自动下一首（`ended`） |

## 三个设计决定，都是"3D 必须有用"

**1. 唱臂角度 = 播放进度，而且可以直接拖。**
真实唱机上针从外圈走到片芯就是一首歌；这里把它做成可交互的进度条 —— **时间有了实体**。
角度不是线性插值：给定"针到圆心的半径" r，用余弦定理反算臂角
`r² = P² + L² − 2PL·cos θ`，所以针真的贴着沟走（线性转臂会让针中途跑到盘外）。

**2. 频谱从唱片边缘长出来，画在唱片所在的平面里。**
它和唱片共享同一次 `rotateX(52°)`，所以是"盘在震动"，不是"UI 在跳"。

**3. 唱片永远是黑的、封套永远是纸的，只有页面（墙）跟随深浅色。**
这两个是"桌上的实物"，换主题不该把它们也漂白 —— 浅色主题下一张黑唱片压在暖纸上，
正好是整页的视觉锚点。**浅色不是把深色反相。**

## 🔴 网易云外链：能放，但没有 CORS（所以频谱是程序化的）

```
302 music.163.com/song/media/outer/url?id=…  →  http://m701.music.126.net/…
```

- **302 那一跳不带 `Access-Control-Allow-Origin`**（末端 CDN 带，没用）。
  ⇒ 一旦 `<audio crossOrigin="anonymous">`，直接 `ERR_FAILED`：**一挂 CORS 连播放都没了**。
  ⇒ 也拿不到真 FFT：`createMediaElementSource()` 对非 CORS 音源按规范输出**静音**，
  那才是"为了频谱把歌弄哑"。
- 302 指向 `http://`，但实测在 https 页面上 Chrome 会自动升级成 https，**线上播放没问题**；
  有问题的只有 CORS。
- 所以那圈短针是**程序化**的：以曲目 id 为种子、以 `audio.currentTime` 为时间轴，
  叠三个不可通约的正弦 + 一个"拍"。它反映的是"针正在沟里走"，不是"我在分析音频"。
  暂停 = 停针 = 环定住，这恰好是对的。
  以后要是把 6 首换成**站内文件**（同源），把 AnalyserNode 那段接回来即可。

## 屏幕 ↔ 平面：透视不是仿射

`.deck__plane` 上只有一次变换 `rotateX(52deg) rotateZ(-7deg)`，外面再乘一个
`scale(s)`。一开始把反解写成"乘一个 2×2 逆矩阵"（等于当正交投影），
结果**盘边误差 ~30%**：900 见方的平面在 `perspective:1600px` 下，近端 `s≈1.33`、
远端 `s≈0.84` —— 拖唱臂时指针和手指会分家。现在的 `screenToPlane` 是闭式解：

```
A = x·cosZ − y·sinZ          B = x·sinZ + y·cosZ
Y2 = B·cosX ,  Z2 = B·sinX    s = k / (k − Z2)      k = 1600
```

`perspective-origin` 是 `50% 42%`（**不是中心**），差的那 72px 也算进去了。
`planeToScreen` 与真实 DOM 变换在中心与盘边三点上的误差都是 **0.00px**（探针断言）。

## 踩过的坑

- 🔴 **放歌的时候抓不住唱臂**（暂停时一切正常，所以极容易漏掉）。
  `#discArt` 一旦转起来（`animation: spin`）就自成**合成层**，在
  `perspective` + `preserve-3d` 的子树里会抢走唱臂的命中测试 —— 指针事件直接
  落到它下面那块 canvas 上。修法：给 `.arm` 显式 `z-index:3`（`.disc` 是 1）。
  顺带把 `animation-play-state` 而不是加/删 class 来控制转动，暂停时盘停在原角度，
  不会"啪"地弹回 0°。
  🔴 同一个坑的另一面：**`document.elementFromPoint` 在这种子树里会说谎**
  （报 `CANVAS`，但真 pointer 事件其实能命中）。判据只能是"真按下去、真拖、
  看 `currentTime`"。
- 🔴 **透视投影下四边形的 bbox 中心 ≠ 它的中心点**（近边放大得多，bbox 整体往近边偏
  ~70px）。验投影必须插一个 0×0 探针元素读 `getBoundingClientRect()`，不能拿
  `#disc` 的 rect 中心当标准答案 —— 第一版就是这么"验失败"的。
- 🔴 **拖唱臂不能拿"指针到支点的距离"当"针到圆心的半径"**：针离支点 216、离圆心 285，
  抓针尖会一下跳到 40%。要按**角度**算。
- `.track__title` / `.track__sub` 必须 `display:block`，否则两个 span 挤成一行
  （`Bb - Rooftop's rainPhrygian · 2021`）。
- 封套的字位放在**顶部**：唱片压在上面，只让出顶部一条横带和左边一条竖带。
  字放下面会被唱片盖掉。
- canvas 上的字体是异步的，`document.fonts.ready` 之后要重画一次，否则字宽不对、排版错位。
- 浅色主题下频谱环要用**深**主色（纸上的浅蓝几乎看不见），而且更短更淡，否则像一圈尖刺。

## 主题与语言

和 `ai-atlas` / `posts-fold` 一样：**没有**切换图标，深/浅色与中/英都由 3D 房子统一控制
（`SitePreferences` 写 `html[data-theme]` / `data-lang`）。`../../_env.js` 只让独立页面
能模拟这套环境，解析优先级 `?theme=` > 宿主预写 `data-*` > 系统，
结果通过 `stageEnv.onChange` 通知本页（文案、封面、片芯、主色、WebGL 底全部跟着重画）。

## 探针（`probe-vinyl.mjs`）

截图看不出来的**空间**断言，一共 25 条：投影正/反解与真实 DOM 一致（±1.5px）、
往返误差 < 0.5px、t=0/1 时针落在 0.95R / 0.38R、真的在放（`currentTime` 前进）、
