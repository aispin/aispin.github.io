# 接触印相 · CONTACT SHEET — 一间摄影房

照片怎么被**看见**？不是再摆一堵卡片墙。摄影房间的空间轴是**连续性** —— 一卷胶片
是连着拍下来的，帧与帧紧挨着。所以这里只有**一条印相带**：12 张按真实画幅排开，
悬在暗房里往深处退。

- 入口：`index.html`
- 在线预览：`/demos/web3d/gallery/`
- 调试参数：`?theme=light|dark`、`?lang=zh|en`（不给就**随系统**）
- 数据：`public/data/pixabay-aispin.json`（构建产物，见「数据从哪来」）
- 探针：`node .workbuddy-ai/harness/probe-gallery.mjs`（23 条）

## 为什么是"带子"

房间之间不能撞车，这是这个站的一条硬规矩：

| 房间 | 空间语言 | 表达什么 |
| --- | --- | --- |
| career | 纵向隧道 | **序列**（一段一段往前走） |
| craft | 环形展板 | **并列**（同时都在） |
| posts | 一条经折长卷 | **长度**（篇数涨了只是带子更长） |
| ai | 弧形卡片墙 | **收藏**（一堆同质的东西） |
| music | 一件实物 | **时间**（针从外圈走到片芯） |
| **gallery** | **一条印相带** | **连续性**（同一双眼睛连着看） |

带子是**环**的：走到第 12 帧，下一帧又是第 1 帧。做成直线的话，停在第 1 帧时
左边永远是空的（右边挤成一摞），画面半边死。

## 三个设计决定

**1. 每帧按真实画幅排，不是统一比例的方格。**
数据里有 3:4 竖、4:3、16:9 横。统一方格 = 把照片当缩略图。真实画幅才对得起
"照片"这件事 —— 竖幅定高、横幅定宽，视觉重量才均衡。画幅收进 [3:4, 16:9] 两档：
8064×6048 那种不收会占掉半屏，带子的节奏就断了。

**2. 带子在深度里起伏。**
每帧有 yaw 倾斜、z 递退、正弦起伏。所以拖动时是"翻过去"，不是"横向滚动"。
远帧 z 更小 ⇒ 透视会把它**放大**，这也意味着帧间距必须留够（`LAY.air = 60`）。
留 14px 时实测 12 帧里有 4 处压在一起。

**3. 相纸永远是纸的，只有屋子跟着主题变。**
浅色不是把深色反相。但浅色下墙也是暖纸（`#F7EDDE`）、相纸 `#F4ECDC` 几乎同色 ——
印相会"陷"进背景里。所以浅色下相纸改成 `#FFFCF6` 并加一道 1px 深边，纸才立起来。

## 交互

| 操作 | 结果 |
| --- | --- |
| 滚轮 / 两指滑动 | 沿带走（一格一帧，90ms 冷却兜惯性） |
| 拖动 | 连续走 —— 不是一格一格跳，带子跟着手走 |
| `←` `→` `↑` `↓` | 换帧 |
| 点一帧 / `Enter` | 抬起来看大图 + 展签 |
| 浮层里 `←` `→` | 翻页；`Esc` 关闭；窄屏左右滑 |
| 点浮层背景 | 关闭 |

## 数据从哪来

页面**不碰** pixabay 接口、也不爬页面 —— 构建时抓一次，存成同源静态 JSON：

```
packages/pixabay-user  ──npm run data:photos──▶  public/data/pixabay-aispin.json
```

```bash
npm run data:photos     # 重新抓 ZEO 的（id aispin-40699950 写在 package.json 里）
```

`packages/pixabay-user` 是独立包（零依赖，靠本机 Chrome 走 CDP），细节见它自己的
README。抓不到 JSON 时房间显示「暂无作品」并把帧清空 —— 空白墙比假数据诚实。

> ⚠️ **版权**：Pixabay Content License 允许商用，但**不允许长期热链**官方 CDN
> （文档写明 URL 24 小时有效）。现在只存 URL 不存图 = 临时展示。真要长跑，
> `pixabay-user` 可以加 `--download`，但 12 张 640 宽合计 3.4MB，进仓库要权衡。

## 踩过的坑

- 🔴 **相纸 `<span>` 吃不到 `width:100%`**：inline 元素忽略宽高，相纸按内容撑开、
  白边跑到照片外面（实测相纸比画面高 26px）。改成 `position:absolute; inset:0`
  把它**钉死**在帧的盒子里，再 `display:flex` 让画面填剩余空间。
- 🔴 **`.frame` 是 `position:absolute`，默认按左上角定位** ⇒ 每帧都往右下偏半个
  身位，整条带子"飘"出画面。锚点要收到自身中心（`left/top` 写负的半宽高；
  `margin:-50%` 不行 —— 百分比参照 `.strip` 的宽，而它是 0）。
- 🔴 **带子的位置不能用"最近一侧"的算法**：跨过接缝那一帧会跳 ±半圈。
  正确做法是把带子坐标折回 `[0, n)`，沿环累加步长（`stripX()`），
  再挑"离当前最接近的等价位置"（差 ±一整圈）。
- 🔴 **浮层不能给 `max-width:1100px`**：竖幅照片只有 500px 宽，盒子却是 1100 ⇒
  照片贴左、右边一大片空白，描述和 tags 又是块级、直接压在相纸上。
  改成 `align-items:center` + `width:fit-content`，宽度交给最宽的孩子。
- 🔴 浮层里 `max-height` 必须**连展签一起算**（`100vh - 330px`），否则竖幅照片
  会把相纸撑满，展签被图片盖住。相纸还要 `box-sizing:content-box`，
  不然 44px 的白边会被图片挤掉。
- **`_640` / `__340` 下划线个数不一样**：只替换最后一个 `_<数字>` 会得到 `__640`，
  CDN 直接 403（12 张里 5 张裂）。见 `packages/pixabay-user` 的 `pickSize`。
- **标题带 SEO 后缀**（`… photo` / `… illustration`），要剪掉。
- 窄屏（≤820px）**不显示顶栏正中的卷名**：三行挤在一起会互相压，
  而底部计数器已经说了"第几张"。
- 浅色下 `--dim-2` 在暖纸上像一行脏点，底部提示要换 `--dim`。

## 主题与语言

和 `ai-atlas` / `vinyl-player` 一样：**没有**切换图标，深/浅色与中/英都由 3D 房子
统一控制（`SitePreferences` 写 `html[data-theme]` / `data-lang`）。
`../../_env.js` 只让独立页面能模拟这套环境。

## 探针（`probe-gallery.mjs`）

截图看不出来的是**空间**断言，一共 23 条：12 帧都建出来 / 帧上有图 /
焦点帧在视口正中（±14px / ±40px）/ 带子**两侧都有帧**（证明是环）/
**帧之间不重叠**（量投影矩形）/ 滚轮上下各换一帧 / `←` `→` 换帧 /
点帧开浮层 / 浮层用 1280 大图 / 展签有像素尺寸 / tags 渲染 /
Pixabay 外链 / 浮层里翻页 / `Esc` 关闭 / 中英文案切得动 / 浅色生效 / 无运行时错误。

```bash
node .workbuddy-ai/harness/probe-gallery.mjs            # 默认打 5199 的 dev
node .workbuddy-ai/harness/probe-gallery.mjs <url>      # 也可以打 dist
```

## 搬进 3D 房间之后

和 `ai-atlas` / `vinyl-player` 同一套路：`RoomGallery` 接管渲染
（`useFrame(cb, 1)`），`GalleryHud` 放这套 DOM。**不要**再在房间里做第二套
主题/语言开关。抓臂/拖动那类 pointer 逻辑可以直接搬过去 —— 它不依赖任何
WebGL 状态。
