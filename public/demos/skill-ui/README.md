# Designer Skill

把 PRD 转成有设计感的交互稿与视觉稿的 AI 设计助手。

输出单文件 HTML 高保真原型、SVG 图形，或全屏 WebGL/GLSL 视觉页。默认支持浅色与深色双主题，**图标一律自绘 SVG，不使用 emoji**。

---

## 它解决什么问题

AI 生成的界面"一眼 AI"，通常不是因为丑，而是：

- 变量太多（五种蓝、四种圆角）
- 层级靠颜色堆
- 间距靠感觉
- 内容是 Lorem ipsum
- 只给 happy path，空态/错误态全靠开发脑补
- 图标用 emoji 凑，跨平台显示不一致
- 炫技压过内容，动效可读性让路
- 一个页面拉五个库，代码比设计还重

这个 Skill 用一套硬性规则把这些坑全堵上。

## 快速开始

1. 把整个 `designer/` 目录放进你的 Skill 目录
2. 确认 `SKILL.md` 的 frontmatter 被平台正确读取（`name` / `description` / `trigger` / `version`）
3. 把 `examples/` 里的 6 个 HTML 存好（如果还没有，可以让 Skill 按第 6 节场景库现场生成）
4. 给 AI 一份 PRD，说"按设计师 Skill 出稿"

## 使用流程（四阶段，中间有闸门）

```
需求解构  →  信息架构与流程  →  交互稿（灰阶）  →  视觉稿（双主题）
   ↓              ↓                  ↓                  ↓
需求摘要      页面清单+状态矩阵    可点击走通        含深色模式
（等确认）    （列全状态）        （HTML）          （HTML/SVG/WebGL）
```

**两个闸门必须停下来等确认**：

1. 阶段 1 结束后，输出《需求摘要》，等用户确认再往下
2. 阶段 2 结束后，输出《页面清单 + 状态矩阵》，状态列全了才进阶段 3

如果 AI 没停，说明需求不够明确，或者 Skill 里的"等确认"写得太软。可以直接说："先给我需求摘要，别往下做。"

## 核心约束（速查）

### 图标

- **严禁 emoji 当图标**，也禁止用 `⚙ → ★ ✓` 这类文字符号
- 全部自绘 SVG，`viewBox="0 0 24 24"`，内容区 20×20
- 描边统一 1.5 或 2，全套一致
- `stroke="currentColor"`，颜色跟随父元素
- 坐标全部是偶数
- 纯图标按钮必须有 `aria-label` 和四态

### 色彩

- 主色面积 < 10%，中性色承担 90% 的信息
- 语义色永远"深字 + 浅底"
- 深色品牌色**单独指定**，不自动推导（红橙黄棕系公式会翻车）

### 暗黑模式

- 必须同时交付浅色和深色，不允许"深色下次补"
- 不用纯黑，画布用 `#0f1319`
- 深色下层级靠明度不靠阴影
- SVG 内联颜色全部走 CSS 变量

### 状态

- 页面级必须覆盖：默认 / 空 / 加载 / 错误 / 无权限 / 离线 / 部分失败 / 超长
- 空态必须有行动出口，不能只写"暂无数据"
- 交互元素必须覆盖：default / hover / focus-visible / active / disabled

### 技术

- 单文件 HTML，零依赖，双击就能开
- 所有数值走 CSS 变量，不写魔法数字
- `:focus-visible` 必须可见
- 375px 下无横向滚动
- **警惕重型依赖**：Three.js / GSAP / Tailwind 一律不引，需要什么手写什么

### WebGL / Shader（当使用 3D 视觉时）

- 手写原生 WebGL + GLSL，不用 Three.js
- `precision highp float`，鼠标 y 轴翻转，颜色走 CSS 变量
- 提供 WebGL 不支持的降级方案
- `document.hidden` 时暂停渲染
- DPR 上限 ≤ 2
- `prefers-reduced-motion` 下静态降级

## 自定义指南

### 换品牌色

打开 `SKILL.md`，改第 2.1 节的 `--brand` 系列：

```css
--brand:#3b5bfd;      /* 主色 */
--brand-h:#2f4ce0;    /* hover，比主色深 10% */
--brand-a:#2338b8;    /* active，比主色深 20% */
--brand-bg:#eef1ff;   /* 浅底，主色的极浅版本 */
```

**如果品牌色是红/橙/黄/棕系**，还要在 `[data-theme="dark"]` 里**单独指定一个深色值**，不要用公式推导。比如品牌色是 `#e74c3c`，深色下可能要用 `#ff8a7a`，直接写死。

### 换字体

改第 2.2 节的 `font-family`。如果换衬线体或等宽体，注意调整行高（衬线体通常需要更高的 `line-height`）。

### 改描边宽度

第 3.3 节的 `stroke-width` 从 1.5 改成 2，会影响所有图标。改完要**重新检查 16px 尺寸下的辨识度**——2px 描边在小尺寸下更容易糊。

### 换个人 IP 名

`examples/06-3d-personal-ip.html` 里需要改的地方：

| 位置 | 查找 | 替换为 |
|---|---|---|
| `<title>` | `ZEO` | 你的名字 |
| `.brand-mark` 内文字 | `Z` | 名字首字母 |
| `.brand` 内文字 | `ZEO` | 你的名字 |
| `.hero-name` | `Z<em>EO</em>` | `<首字母><em>剩余字母</em></em>` |
| 页脚版权 | `ZEO` | 你的名字 |

`hero-name` 的结构是"首字母实色 + 后半段渐变"，保证两个字母以上都能撑起超大号排版。

### 加新场景

在 `SKILL.md` 第 6 节追加一个 `### 6.7 xxx`，按现有格式写：考察点、必含元素、验收要点、常见错误。同时在 `examples/` 里加一个对应的 HTML。

## 常见问题

**Q：AI 生成的图标质量不稳定怎么办？**

在提示里明确说："图标按 SKILL.md 第 3 节执行，24×24 viewBox，内容区 20×20，stroke-width 1.5，currentColor，逐条走 3.10 验收清单。"

**Q：生成的深色模式有明显问题（比如白底穿帮）怎么办？**

大概率是 SVG 里硬编码了颜色。检查所有 `<rect>` / `<path>` 的 `fill` 和 `stroke`，全部改成 `var(--n-*)` 或 `currentColor`。

**Q：场景库都不匹配我的需求怎么办？**

挑两个最接近的作为基准，明确告诉 AI："参考 demo 02 的数据密度和 demo 04 的表单排版。"不要让 AI 从零开始，否则会退回到通用套路。

**Q：为什么不用 Three.js？**

三个理由：

1. **零依赖是硬规则**。Three.js 是 600KB 起步的外部依赖，一旦引入，"双击即开"就没了
2. **大多数场景不需要它**。个人 IP 页的核心视觉是流体场，一个 fragment shader 铺满全屏，比 Three.js 渲染一个场景再叠后处理，代码量少 90%、性能高一个量级
3. **shader 就是 shader**。Three.js 只是 shader 的宿主，不生产视觉效果，只帮你管理 buffer 和 uniform。手写 40 行 WebGL 初始化，换来完全的控制权

**Q：如何判断生成的质量是否达标？**

三个快速检验：

1. 把稿子缩到手机屏幕宽度，看有没有横向滚动
2. 切换到深色模式，看有没有残留的浅色元素
3. 数一数主色出现了几次，超过 5 处就不合格

如果涉及 3D 页面，再加一条：

4. 用低端设备（或 Chrome DevTools 的 CPU throttling）打开，看动效是否卡顿

**Q：如何让 AI 停下来等确认？**

明确说"按四阶段走，第一个闸门停下等我确认"。如果它还在往下做，说明需求里缺关键信息（平台/用户/核心任务），补上再试。

**Q：3D 页面性能不好怎么办？**

按优先级依次降级：

1. 检查 DPR 上限是否 ≤ 2（4K 屏不要跑 DPR=3）
2. 检查 `document.hidden` 时是否暂停了渲染
3. 降低 shader 里的噪声层数（三层可以减到两层）
4. 缩小 canvas 分辨率（CSS 尺寸不变，canvas 内部 `width/height` 减半）
5. 最后才考虑用静态 SVG 渐变替代 shader

## 设计哲学

这份 Skill 不是要限制创意，而是要消灭那些**不该浪费创意去解决的问题**。

颜色变量、间距栅格、图标网格、状态覆盖——这些是地基，做对了没人会夸，做错了整个稿子就塌了。把它们变成硬性规则，你才能把精力留给真正需要判断力的部分：这个流程顺不顺，这个层级对不对，这个 CTA 够不够有力。

同理，"不用 Three.js"不是反技术，而是**把复杂度花在真正需要的地方**。一个流体场背景，40 行原生 WebGL 就够了，剩下的 600KB 应该留给内容。

**规则存在的意义，是让你不用再想规则。**
