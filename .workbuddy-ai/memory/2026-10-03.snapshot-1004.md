## 画廊黑卡片根因（重大 bug 修复）
- **症状**：画廊「晾衣绳」上 8 张摄影卡片全黑（6 倍提亮后仅见标题文字），无 console error。
- **根因**：卡片 front 指向 `/gallery-{morning,garden,rain,seaside}.svg`。three.js 的 WebGL 纹理用**不可变存储**（texStorage2D），SVG 解码后的第二次上传被驱动拒绝：
  `GL_INVALID_OPERATION: glTexImage2DRobustANGLE: Texture is immutable.`
  上传静默失败 → sampler 返回黑。**只报 GL warn，不报 error**，所以一直没被发现。
- **结论：本项目禁止把 SVG 交给 three.js 当纹理**。要么预转成位图，要么 canvas 现画。
- **修复**：新建 `src/utils/photoPlaceholder.js`（纯 Canvas 2D，768×1024 = 卡片 1.5×2 的 3:4），
  8 个程序化场景 morning/garden/rain/seaside/evening/green/night/coast，按 variant 缓存 CanvasTexture。
- `src/data/photography.json`：8 条的 `front`/`painted` 两个 SVG 字段 → 换成 `placeholder: "<variant>"`；
  描述文案同时从「摄影素材待替换」改成真实短句。`useContentData.preload()` 对 placeholder 项直接 return。
- `GalleryRoom.jsx`：`projectTextures`/`paintedTextures` 改为「procedural + 文件」混合构建
  （`useTexture` 仍恒定调用，无文件时传 1×1 透明 data URI 占位，保持 hook 元数稳定）；
  `projects` useMemo 补全 deps + `techStack` 加 `|| []` 兜底。
- 4 个 SVG 移出 `public/` → `/tmp/aispin-removed/gallery-svg/`（未引用）。
- 验证：画廊 GL 报错归零（仅剩 headless 的 KHR_parallel_shader_compile 提示），0 error / 0 失败请求。

## 判定「是否已上色」的正确方法
- 用 PIL 扫全站贴图算 HSV 平均饱和度：本项目是**墨线+纸底**风格，绝大多数贴图 meanS < 5 属正常，
  studio 的 `_painted` 也只有 6-11 —— 它们是**石墨排线稿**，不是「未上色」。
- 真正的「未上色」信号不是低饱和，而是**被 flat `#e0e0e0` 材质渲染的纯线稿**（云）或**根本渲染不出来**（SVG 黑卡）。
