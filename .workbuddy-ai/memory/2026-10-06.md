### `ink-splash.webp` → `makeInkSplashTexture()`
点击瓢虫彩蛋的墨点爆点：2×2 平面，初始 `scale=[0,0,0]`，点击后 gsap 弹到 0.8 再淡出。
生成器加在 `src/utils/entranceArt.js`（本来就是 entrance 那 4 张位图的替代品）。
canvas **500×500**（1:1 对 2×2 平面），导出 `INK_SPLASH_ASPECT`。

**三个坑（都留了注释）：**
1. **不能按轴缩放半径**。`cos(a)·r·SX` 会把 12 点方向的针状尖刺横向压扁，
   画出来是**矩形烟囱**。正确做法：先在圆坐标里画完，再 `ctx.scale(SX,SY)` 整体拉伸。
2. **尖刺不能用「角度上的三角半径剖面」**。`r += len·(1−d/w)` 在峰值落在两个采样点
   之间时会**削平尖端**，同样得到矩形。改成**显式三角形**（底边两点 + 顶点）才对。
3. **画大再框小**。900×750 scratch 上画，用现成的 `alphaBBox()` 量实际墨迹外接框，
   等比缩进 500×500（占 90%）。这样随机尖刺永远顶不到画布边被切平。

形状：有机块 + 6 宽楔 + 5 细针 + 2 长须 + 2 附带小叶 + 52 飞溅点 + 12 喷雾线
+ 4 下淌墨滴，整体倾斜 −0.18 rad（参考图是左下→右上走向）。

## 更新 ⑯ — 音效：两个从来没响过的声音 + 首屏 1.8 MB 的 ogg

### 起因与结论

清完位图之后顺手核了 `public/sounds/`（8.8 MB，`public/` 里最大的一块）与
`play()` 的调用点，发现**音频这一层从来没被验证过**。逐个对：

| `play(name)` | 调用点 | 结果 |
|---|---|---|
| `pencil` | `Preloader.jsx:228`（循环） | 🔴 `/sounds/pencil.mp3` 不存在 |
| `tear` | `Preloader.jsx:311`、`PaperTransition.jsx:158`、`:201` | 🔴 `/sounds/tear.mp3` 不存在 |
| 其余 5 个 | 门 / 房间 | ✅ 有文件 |

罪魁是 `AudioManager.jsx` 里的兜底：`soundPaths[name] || \`/sounds/${name}.mp3\``。
`soundPaths` 只登记 5 个键，兜底却把任何没登记的名字**拼成一个请求**。后果：
铅笔声（进度条那 2~10 秒）和撕纸声**从来没响过**；而且 `PaperTransition` 每次
传送要触发**两次** `tear`（closing + opening），所以**每进一个房间就是 2 条 404**，
加上进站那次，每次访问至少 2 条。

第二件事：`initAudio()` 是 `App.jsx:196` **挂载时**调的，里面
`preload='auto'` + `.load()` ⇒ **每个访客首屏下载 1.8 MB 的 ogg**，
哪怕从不点播放 / 已静音 / 选的是合成 BGM（`bgmSource` 默认 `'mp3'`，
但项目本来就有零字节的 `src/audio/bgm.js`）。

### 改法

1. **新增 `src/audio/paperSfx.js`**（程序化，零素材，沿用 `bgm.js` 先例）
   - `pencil`（循环）：白噪 → bandpass 2100Hz(Q0.7) → highpass 560Hz；
     增益叠两个**互不成谐波**的 LFO（3.6Hz/0.30 + 8.9Hz/0.10）做笔触强弱，
     顺便让 2.5s 循环听不出周期。
   - `tear`（一次性，0.42s）：白噪 → bandpass **620Hz 指数上扬到 3900Hz** →
     包络切成 **10 段微脉冲**（纤维一根根崩断，不是平滑的「嘶——」）。
   - 句柄刻意与 `HTMLAudioElement` 对齐（`muted`/`volume`/`_baseVolume` 三个
     字段用 getter/setter 映射到各自的 gain 节点）⇒ `AudioManager.jsx` 里那套
     「全局静音 + 全局音量」的 `useEffect` **一行都不用分叉**。
2. **`AudioManager.jsx`**：`soundPaths` 提到模块级改名 `SOUND_PATHS`，
   **删掉兜底**；未登记的名字改成 DEV 下 `console.warn`，不再发请求。
3. **`utils/audioManager.js`**：`initAudio()` 只同步静音状态；元素挪到
   `ensureBgMusicAudio()`、`preload='none'`，只在真正 `play()` 时取；
   音量改存模块变量 `bgVolume`（没播过就拖音量条也不会丢）。
4. 删掉 `AchievementsContext.jsx:17` 的 `const { playSound } = useAudio()`
   —— `AudioContext` 从来没提供过 `playSound`，它一直是 `undefined`。

### ⚠️ 关键坑：用户手势之前不能建 AudioContext

Chrome 在无手势时 `new AudioContext()` 会打
`The AudioContext was not allowed to start...`，且必然 `suspended`。
而 `play('pencil')` 是 **Preloader 挂载时就调**的，早于任何点击 ⇒
直接建 context 等于「拿一条控制台警告换两条 404」。

所以模块做成**手势门控**：手势前**不建 context**；一次性音效直接放弃
（等价于它今天「404 后静音」）；**循环音效挂起**（`armedLoops`），
第一个手势到达再补播（铅笔声本来就是「加载期间一直在划」，语义正确）。
解锁事件只认 `pointerdown`/`touchstart`/`keydown` ——
**`wheel` 不算 user activation**，加进去会解锁出一个仍 suspended 的 context。

### 新增 harness：`.workbuddy-ai/harness/audio-check.mjs`

截图验证不了声音，于是在 `AudioContext.destination` 前挂 `AnalyserNode` 旁路，
读时域数据算 **max RMS**（RMS>0 才算真的发声）。踩到并记下的三个坑：

1. **`connect()` 在 `AudioNode.prototype` 上，不在 `AudioContext.prototype` 上。**
   挂错原型会**静默失效**（`origConnect` 是 undefined，被 try/catch 吞掉）。
2. **页面里会同时有 2 个 AudioContext**（实测 `ctxs: 2`）：合成音效用
   `paperSfx` 的，成就铃声用 `AchievementsContext.jsx:49` 自己 `new` 的。
   所以旁路探针必须**按 context 存一组**，只留最后一个会被后建的顶掉 ⇒
   测出来全是 0（这个假阴性骗过一次）。
3. **无头下 `setTimeout` 被严重节流**（实测 900ms 只跑到 2 帧）。
   音频图在独立线程渲染，所以要用**同步自旋**采样，不能 `await sleep`。
   同理，句柄契约断言必须**相对底噪**：Preloader 的铅笔声在加载没结束时
   本来就该在响（实测底噪 0.058；加 `?noloader=1` 后底噪精确为 0）。

### 🔴 这一轮踩到的两个真坑（都值得记）

**1. `new Map(arrayOfArrays)` 会静默丢字段。**

我的场景图探针就栽在这：`prev.get(uuid)[2]` 拿到的是 tag 字符串的第三个字符
`'e'`，于是**每个物体都被判成"变了"**，报出 1316/1316 在动 —— 看起来像
「开了减少动态还在动」，其实是探针自己的 bug。**显式 `.map(([k,v]) => [k,v])`。**

**2. 探针必须先在对照组里证明"真的会动"。**

## 🔴 本轮最重要：`manualChunks` 让生产构建白屏

**症状**：dev 完全正常（`meshes 701`、0 报错），生产 `rootChildren: 0`、
`hasCanvas: false`，唯一报错
`Cannot set properties of undefined (setting 'Activity')` —— React 根本没挂载。

**根因**：`vite.config.js` 用 **子串**判包名：

```js
if (id.includes('@react-three')) return 'r3f';   // ← 子串，不是路径段
```

而 `node_modules/@react-three/fiber/node_modules/scheduler` 的路径**也含
"@react-three"**，于是这份嵌套的 scheduler 被判进 `r3f` chunk。后果是
`react` ⇄ `r3f` 互相 import 成环 —— 因为 `react` chunk 需要 Rollup 的
`_interopDefault` helper（`function jr(e){return e&&e.__esModule&&...?e.default:e}`），
而那个 helper 恰好落在 `r3f` 里。ES 模块允许循环引用，但这条环穿过 CJS→ESM
包装器，React 的 exports 对象还没建好就被赋值 → 白屏。

**修法**：包名一律取**最后一个 `node_modules/` 之后**的段（`packageOf(id)`，模块级函数）。

**验证**：`react` chunk 现在 import 列表为空；环检测 ✅ 无环；
生产 smoke 回到 `meshes 701`、`ERRORS (0)`，与 dev 完全一致。

**两条教训**：
1. `id.includes('包名')` 判 chunk 归属**一定会被嵌套依赖咬到**。嵌套依赖无处不在
   （本例 `@react-three/fiber/node_modules/scheduler`）。
2. **dev 永远不会暴露这类问题** —— dev 不打包，模块各自独立求值，循环引用无害。
   所以「dev 好的」不能当作「构建好的」；**生产冒烟是必须的**，不是可选项。

新增 harness `.workbuddy-ai/harness/chunk-graph.mjs`：chunk 依赖图 + 直接双向环 +
DFS 深度环 + react chunk 体积体检（< 120 KB 视为规则误分类），退出码可直接接 CI。
